01

Introducción

Grupo Helse S.A.S. es una empresa colombiana dedicada a la comercialización y distribución de productos para el sector salud. Para este ejercicio pedagógico se simplifica su operación y se representa el flujo básico desde el registro del cliente y la generación del pedido hasta el alistamiento y el envío.

El modelo no pretende reproducir toda la operación real de la empresa; delimita un escenario comprensible para aplicar los conceptos de bases de datos.

02

Conceptos fundamentales

Haz clic en cada concepto para desplegar su definición y uso.

▭Entidad+

Objeto del negocio sobre el cual se almacena información: Cliente, Pedido, Producto y Envío.

⬭Atributo+

Característica que describe una entidad o relación, como nombre, costo o cantidad.

│Campo+

Columna de una tabla en la que se registra un tipo específico de dato.

◇Relación+

Asociación que representa una regla del negocio: genera, contiene o alistamiento.

A̲Clave+

Atributo que identifica de manera única cada registro, como ID_CLIENTE.

↔Cardinalidad+

Indica cuántas ocurrencias de una entidad pueden vincularse con otra.

03

Modelo entidad–relación

Notación de Peter Chen aplicada al escenario simplificado.

01

CLIENTE — GENERA — PEDIDO

Un cliente puede generar varios pedidos; cada pedido corresponde a un cliente.

02

PEDIDO — CONTIENE — PRODUCTO

Un pedido contiene productos y un producto puede aparecer en distintos pedidos. Cantidad pertenece a la relación.

03

PEDIDO — ALISTAMIENTO — ENVÍO

El pedido preparado origina el envío que llevará los productos al destino.

04

Modelo relacional

Transformación del modelo conceptual en tablas, claves y relaciones.

Lectura del modelo

La relación de muchos a muchos entre PEDIDO y PRODUCTOS se resuelve con PRODUCTOS_PEDIDO. Como un envío puede registrar varios métodos, METODO_ENVIO se conserva como estructura separada vinculada con ENVIO.

05

Conclusiones

  1. El modelo entidad–relación permite comprender el negocio antes de construir las tablas.
  2. Las entidades, atributos, relaciones y cardinalidades convierten reglas del negocio en una estructura organizada.
  3. El modelo relacional traduce el diseño conceptual a tablas conectadas mediante claves.
  4. La simplificación facilita analizar el flujo cliente–pedido–envío.
