01

Introducción

Modelo empresarial

Grupo Helse S.A.S. es un grupo empresarial colombiano dedicado a la operación logística y de distribución en el sector salud. Cuenta con una línea de operación logística dedicada a la comercialización, el almacenaje y la entrega nacional de productos farmacéuticos, fórmulas nutricionales, dispositivos médicos e insumos. Dentro de su operación se desarrollan diferentes actividades relacionadas con la gestión de clientes, la recepción y generación de pedidos y el posterior proceso de envío de los productos. Debido a la cantidad de información que se genera en estas actividades, es importante contar con una estructura que permita organizar los datos de manera adecuada y representar claramente la relación entre los diferentes procesos.

Con el propósito de representar una parte del proceso operativo de la empresa, se desarrolló un modelo entidad–relación (E/R), en el cual se identifican las principales entidades que intervienen en el proceso y la forma en que estas se relacionan. El modelo representa la lógica utilizada por la compañía desde que un cliente realiza un pedido hasta que este es asociado con su respectivo envío.

02

Construcción de la base de datos

El diseño avanza desde la comprensión del negocio hasta su implementación en un sistema gestor.

La construcción de una base de datos se organiza en tres fases porque cada una responde una pregunta diferente: qué información necesita el negocio, cómo se organizará esa información y cómo se implementará técnicamente. Separar estos niveles permite comprender primero la realidad empresarial sin depender de un programa específico y transformar después ese conocimiento en una estructura que pueda implementarse en un sistema gestor de bases de datos (Navathe & Pernul, 1992).

01

Fase conceptual

Representa el negocio mediante entidades, atributos, relaciones y reglas. El modelo E–R facilita la comunicación entre usuarios y diseñadores (Storey et al., 2015).

02

Fase lógica

Transforma el modelo conceptual en tablas, columnas, claves primarias y claves foráneas, todavía sin depender de un gestor específico (Navathe & Pernul, 1992).

03

Fase física

Implementa las tablas en un gestor y define tipos de datos, restricciones e índices según las necesidades de almacenamiento y rendimiento (Teorey et al., 2011).

FASE 1 · CONCEPTUAL

Modelo entidad–relación

Primero se interpretan las reglas del negocio y se representan las entidades, sus atributos y las relaciones que las conectan, sin decidir todavía tipos de datos o características de un programa específico.

01

CLIENTE — GENERA — PEDIDO

Un cliente puede generar varios pedidos; cada pedido pertenece a un único cliente.

02

PEDIDO — CONTIENE — PRODUCTO

Un pedido contiene varios productos y un producto puede aparecer en diferentes pedidos. Cantidad describe esta relación.

03

PEDIDO — ALISTAMIENTO — ENVÍO

El pedido preparado queda asociado con el envío que transporta los productos a su destino.

FASE 2 · LÓGICA

Del modelo E–R al modelo relacional

Las entidades se convierten en tablas, los atributos en campos y las claves identifican o conectan registros. La cardinalidad guía la transformación de cada relación.

FASE 3 · FÍSICA

Implementación y gestión en SQL

El modelo lógico se implementa en un sistema gestor de bases de datos. Aquí se definen tipos de datos, restricciones, índices, claves primarias y foráneas, y reglas de integridad para que la información pueda almacenarse y consultarse con seguridad.

Decisiones de implementación

  • Asignar tipos como INT, VARCHAR, DATE y DECIMAL.
  • Crear claves primarias para identificar cada registro.
  • Aplicar claves foráneas según las cardinalidades.
  • Definir restricciones para valores obligatorios y válidos.
  • Preparar consultas para trazabilidad, inventario y entregas.

Análisis de datos

Hallazgos del modelado

El diseño permite reconocer necesidades de información antes de crear físicamente la base de datos.

01

La remisión conecta el proceso

Permite seguir el pedido desde su registro y estado hasta el envío asociado.

02

La cantidad pertenece al detalle

No describe por sí sola al producto ni al pedido; depende de la combinación entre ambos.

03

El historial del cliente se conserva

La relación uno a muchos permite consultar todos los pedidos realizados por un mismo cliente.

04

El envío admite varios métodos

Separar METODO_ENVIO evita repetir los demás datos del envío cuando existen múltiples valores.

04

Conclusión

El desarrollo del modelo de base de datos permitió representar de manera organizada una parte del proceso logístico de Grupo Helse S.A.S., desde el registro del cliente y la generación del pedido hasta la selección de productos y la gestión del envío. El modelo entidad–relación facilitó la identificación de las entidades, los atributos, las relaciones y las cardinalidades que expresan las reglas del negocio; posteriormente, el modelo relacional transformó estos elementos en tablas conectadas mediante claves primarias y foráneas. Esta estructura proporciona una base coherente para implementar la solución en SQL, reducir la duplicación de información, mantener la integridad de los datos y facilitar la trazabilidad de los pedidos dentro de la operación empresarial.
